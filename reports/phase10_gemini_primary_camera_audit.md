## A. Executive Summary

Phase 10 transitions the AgroSense plant pathology computer vision subsystem to a **Gemini Vision Primary Architecture** while rigorously preserving the project's verified, proprietary V2 ONNX neural models (`classifier_v2.onnx`, `detector_v2.onnx`) in an inactive, fully compilable, zero-degradation state.

### Key Achievements:
1. **Zero Model Alteration**: 100% cryptographic SHA-256 bit-for-bit parity verified across all existing ONNX models, quantization data, class mappings, PyTorch checkpoints, and audit manifests.
2. **Decoupled Provider Abstraction**: Introduced a unified `IPlantAnalysisProvider` interface with runtime provider switching (`GeminiProvider` active, `ONNXProvider` preserved).
3. **Zero Browser Credential Leakage**: Strict server-side route (`/api/analyze-plant`) encapsulates `GEMINI_API_KEY`. No API keys or secret environment variables are bundled into client JavaScript.
4. **Structured JSON Output & Schema Validation**: Gemini Vision generates structured outputs with server-side runtime type, taxonomy, severity, and bounding-box validation.
5. **Truthful Bounding Box & Confidence Semantics**: Abolished synthetic fallback bounding boxes; only valid normalized coordinates `[0.0, 1.0]` generated by Gemini are rendered. AI confidence estimates are explicitly separated from experimental classifier test accuracies.
6. **Robust UX & Rate Limiting**: Implemented a discrete `capture → analyze → result` pipeline with single-active-request locking, snapshot retention, live view return, and sample testing capability.
7. **Complete Decoupling from IoT Hardware**: AI camera vision functions independently of ESP8266 WebSocket connectivity.

## D. Gemini Provider Implementation

The `GeminiProvider` class implements `IPlantAnalysisProvider` and handles:
1. **Frame Capture & Dimension Optimization**: Downscales high-resolution camera frames to a maximum dimension of 1024px, encoding as JPEG at 0.88 quality (~150-300KB) to preserve fine lesion texture without saturating bandwidth.
2. **Single Active In-Flight Lock**: `this.isAnalyzing` mutex prevents duplicate request dispatches while a call is in flight.
3. **HTTP Transport**: Dispatches to `/api/analyze-plant` with proper headers and JSON payload.
4. **Latency Measurement**: Records total round-trip client-to-server latency in milliseconds.
5. **Strict Provenance**: Injects `provider: "gemini"` into the canonical result contract.

## G. Centralized Provider Selection Architecture

Provider switching is isolated in `src/ai/providers/index.ts`:

```typescript
export const ACTIVE_AI_PROVIDER: "gemini" | "onnx" =
  (import.meta.env.VITE_AI_PROVIDER as "gemini" | "onnx") || "gemini";

export function getAIProvider(override?: "gemini" | "onnx"): IPlantAnalysisProvider {
  const target = override || ACTIVE_AI_PROVIDER;
  if (target === "onnx") {
    return getONNXProvider();
  }
  return getGeminiProvider();
}
```

No conditional `if (gemini)` / `if (onnx)` branches are scattered across UI components. All components consume the canonical `PlantAnalysisResult` contract.

## I. Image Pipeline & UX Flow

The camera flow follows a disciplined discrete lifecycle:
1. **Camera Preview**: Live 640x480 video feed from environment/rear camera.
2. **User Snapshot**: User aligns foliage and clicks **"Capture & Analyze Frame"**.
3. **Freeze & Loading**: Frame is converted to JPEG and frozen on screen while showing **"Analyzing with Gemini Vision..."**.
4. **Result Presentation**: Bounding box is drawn over the frozen snapshot, along with diagnosis, scientific name, severity, confidence, evidence, and recommendations.
5. **New Scan**: User clicks **"New Scan / Live View"** to unfreeze and restart camera stream.

Continuous 30fps streaming to Gemini is strictly prohibited, eliminating quota exhaustion, latency jitter, and unnecessary billing.

## K. Bounding Box Validation & Fail-Closed Guarantee

Bounding box coordinates returned by Gemini Vision undergo server-side validation:
1. Coordinates must satisfy $0.0 \le x \le 1.0$, $0.0 \le y \le 1.0$, $0.0 \le width \le 1.0$, $0.0 \le height \le 1.0$.
2. Negative values or `NaN` are immediately discarded.
3. Micro-boundary floating-point overflows (e.g. $x + width = 1.002$) are clamped safely to $1.0 - x$.
4. If Gemini returns `null` or the leaf/plant is not detected, `bounding_box` is set to `null`.
5. The UI draws **NO BOX** when `bounding_box` is `null`. All artificial/synthetic fallback boxes have been permanently removed.

## M. Error Handling Matrix

| Error Scenario | Server Response Code | Client Handling & UI State |
|---|---|---|
| Camera permission denied | N/A (Client DOM) | `StateOverlay (error)`: "Camera Access Denied. Enable permissions in settings." |
| Camera hardware missing | N/A (Client DOM) | `StateOverlay (error)`: "Camera hardware unavailable." |
| Invalid / non-image upload | `415 Unsupported Media` | Error banner displayed: "Unsupported format. Supported: JPEG, PNG, WEBP." |
| Payload exceeds 10MB | `413 Payload Too Large` | Error banner displayed: "Image exceeds 10MB limit." |
| Missing `GEMINI_API_KEY` | `500 Internal Error` | Error banner: "Server configuration missing Gemini API Key." |
| Gemini rate limit / timeout | `503 / 429 Error` | Error banner with sanitized message; camera remains ready for retry. |
| Non-plant image (hand/tool) | `200 OK (plant=false)` | UI displays `NO PLANT DETECTED` with 0% anomaly, no box rendered. |
| Insufficient visual evidence | `200 OK (class=unknown)` | UI displays `UNCERTAIN OBSERVATION` with request to capture closer frame. |
